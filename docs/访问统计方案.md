# 访问与游玩统计：轻量方案

可以在现有网页结构上增加。游戏和题库继续由 GitHub Pages 托管；要让所有访客共享统计数据，需要一个云端存储服务。只用 `localStorage` 只能记录当前浏览器的数据，不能汇总所有人的结果。GitHub Pages 提供的是静态托管，不能直接接收请求并写回题库 JSON。[GitHub Pages 官方说明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)

推荐 **Cloudflare Workers + D1**：Worker 是接收统计请求的小程序，D1 是保存记录的数据库。它们运行在云端，不需要租用并维护一台服务器，也不需要保持你的电脑开机。网页仍使用当前纯 HTML、CSS、JavaScript。[D1 官方入门](https://developers.cloudflare.com/d1/get-started/)

这不是完全没有后端，而是将很小的后端交给云服务运行。低访问量可以先使用免费额度；是否够用取决于实际请求和数据库使用量，不保证永久免费或无限制。[Workers 计费](https://developers.cloudflare.com/workers/platform/pricing/)、[D1 计费与免费限额](https://developers.cloudflare.com/d1/platform/pricing/)

## 先明确统计口径

| 项目 | 建议第一版的定义 |
| --- | --- |
| 开始人次 | 点击“开始游戏”并新建一局时 +1；重新开始也算新的一局 |
| 成功通关人次 | 全部答案输入正确后 +1；同一局只能计一次 |
| 平均完成用时 | 成功局的用时总和 ÷ 成功局数；无人完成时显示“暂无”，不显示0秒 |
| 独立开始人数／完成人数 | 如确实需要“人数”，用浏览器保存的匿名ID按关卡去重；同一人换设备、清除数据后仍可能重复 |

“人次”较容易解释和实现；匿名去重只能近似独立访客，无法保证是真实的人数。

每个英文/片假名关卡已有独立的 `level.id`，可直接分别汇总。若将来修改答案或剧情线索，应增加题目版本字段或更换 ID，避免新旧题的用时混在一起。可以另外按游玩模式统计，以免辅助与挑战成绩失去比较意义。

## 与当前游戏规则对应

- 网页创建新的 `GameSession` 时发开始事件；界面语言切换、辅助/挑战切换、打开后取消设置，不算新开一局。
- 只有 `session.finishReason === 'solved'` 才发通关事件。
- 挑战模式的“结束并公布答案”是 `revealed`，不能算成功通关，也不进入平均用时。
- 辅助模式查看单个答案不算通关；若后来全部填对，可记为“使用过答案帮助的通关”。如果需要比较挑战模式成绩，应记录本局是否**曾经使用辅助模式**、查看答案数与查询数，不能只看结束瞬间的模式。
- 每局有独立的 `runId`；云端对它设唯一限制，让重试和重复回调不重复计数。
- 断网或统计服务故障时，游戏正常继续；显示的总量可能漏掉未成功上报的局。以后可以增加重试队列。

## 大致部署流程

1. 注册 Cloudflare 账号，创建一个 Worker 项目和一个 D1 数据库。
2. 建一张游戏记录表，保存：`runId`、`levelId`、匿名访客ID（如需人数）、开始时间、是否通关、通关用时、是否用过辅助。
3. 给 Worker 绑定数据库，并提供三个接口：开始一局、提交通关、读取某关卡汇总。读接口只返回汇总，不返回访客明细。
4. 设置允许你的 GitHub Pages 域名访问这些接口；本地调试时单独允许本地网址。跨域限制有助于网页正常访问，但不是防刷机制。
5. 用已经安装的 Node.js 和官方工具 Wrangler 在本地测试，再发布 Worker，获得云端接口网址。无需更换当前网页框架。
6. 在网页中配置接口网址，接入开始/通关事件和关卡统计显示，再按现有方式发布 GitHub Pages。
7. 检查刷新页面、重新开始、切换模式、提前结束和网络重试不会重复记通关；再检查实际匿名访客数据是否能汇总。

官方教程允许通过控制台或命令行完成 Worker、数据库与绑定；部署完成后，日常游玩不需要运行本地服务。[Cloudflare 官方步骤](https://developers.cloudflare.com/d1/get-started/)

公开的匿名统计只能用作参考；接口仍需要校验关卡、时长和重复提交，并按需要增加请求频率限制。数据库管理权限和服务端凭据不放在前端代码或公开 GitHub 仓库中。

## 如果希望更省事

只在站长后台看数据，可以使用支持自定义事件的托管分析服务，发送“开始”和“通关”事件、关卡ID及用时。这样通常免去自写数据库接口；但把每关汇总直接展示在游戏网页上，仍要看该服务是否提供合适的公开统计接口、费用与权限控制，平均用时也需正确配置。

本次仅提供方案，未创建云端账号或数据库，也没有让游戏向外部发送访问数据。当前网页保持本地游戏功能，等确定统计口径和服务后即可接入。
