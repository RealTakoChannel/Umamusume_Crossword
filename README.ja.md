# トレセンクロスワード部

[简体中文](README.md) · [English](README.en.md) · **日本語**

『ウマ娘』のキャラクター名とmaimai DXの英語曲名を解答に用いた多言語クロスワードゲームです。HTML・CSS・JavaScriptで実装し、問題集・名前/楽曲辞典・ヒントの出典をJSONで管理します。ゲームロジックとDOM操作を分離した構成です。

画面とヒントは簡体字中国語・英語・日本語に対応。解答の文字は英字とカタカナから選択でき、画面言語とは独立しています。現在は5種類の問題集、9つの問題、97人分の名前辞典と22曲の楽曲辞典を収録しています。

maimai問題集の解答は英語曲名のみで、全曲が13〜15（13+・14+を含む）のSTD/DX譜面を持ちます。落雪APIのアーティスト・コミュニティ別名・BPM・譜面レベルからヒントを生成し、曲名・アーティスト・別名で検索できます。数字を含む曲名と英語以外の曲名は初版の対象外で、カタカナ版はありません。[データ出典と更新方法](docs/舞萌DX题库与来源.md)を参照してください。

## 機能

| 機能 | 動作 |
| --- | --- |
| 問題選択 | 問題集・解答の文字・個別の問題を指定 |
| アシストモード | 単語全体が正解すると緑色で表示し、3言語の名前を公開。名前検索は無制限 |
| 解答の表示 | アシストは回数無制限で表示のみ。チャレンジは異なる3問まで自動入力し、緑色で固定。時間は進み、再表示は回数を消費しない |
| チャレンジモード | 未表示の解答は全問正解まで正誤を非表示。空欄以外の名前検索は3回までで、該当なしも1回として数える。検索と解答表示の回数は独立 |
| 途中終了 | 両モードでゲームを終了して計測を止め、全解答を公開。通常クリアとは別の終了状態 |
| 名前検索 | 中国語・英語・かな・名前の一部・登録済み別名で検索し、3言語の名前を表示 |
| 入力 | キーボード移動、交差マスでの方向切替、単語の貼り付け、日本語IMEに対応 |
| 設定変更 | 画面言語・モードの変更では盤面、時間、使用済み回数を保持。別の問題や解答文字を適用すると新しいゲームを開始 |
| クラウド統計 | 問題・内容バージョン別の開始数、クリア数、平均時間を3言語で表示。全程チャレンジの結果も別に集計 |

セッション作成時に計測を開始し、全問正解または途中終了の確定時に停止します。設定・検索・解答のダイアログを開いても時間は進みます。検索とチャレンジの解答表示は別々に数え、モード変更では回数を回復しません。アシストでの解答表示はチャレンジの回数に含めず、チャレンジで表示したマスはモード変更後も固定します。解答表示を使ったクリアは総数に含め、解答表示なしのチャレンジ統計には含めません。

## 開発環境とコマンド

Node.js 24で動作を確認しています。サードパーティーのnpmパッケージを使用していないため、依存関係のインストールは不要です。ブラウザーにはES Modules、Fetch API、ネイティブの `<dialog>` が必要です。

```sh
npm run dev
```

開発用サーバーは `http://localhost:5173/` で起動します。モジュールとJSONを読み込むため、HTTP経由でページを開いてください。

| コマンド | 用途 |
| --- | --- |
| `npm run dev` | プロジェクトのルートをローカル配信 |
| `npm run check:data` | 問題、名前辞典、対になる問題、出典データの整合性を検証 |
| `npm test` | Node.js標準のテストランナーでロジックとデータを検証 |
| `npm run build` | データを検証して `dist/` を再生成 |
| `npm run build:worker` | 統計Worker用の問題バージョンと正解盤面を生成 |
| `npm run preview` | ビルド後の `dist/` をローカル配信 |

Windows PowerShellでは必要に応じて `npm` を `npm.cmd` に置き換えてください。`启动游戏.cmd` はWindows向け開発プレビューの起動用ファイルです。サーバーは環境変数 `PORT` を参照します。開発用と成果物用のプレビューはいずれも既定で5173番を使うため、同時起動する場合は別のポートを指定します。

## 実行時の構成

`catalog.js` が名前辞典と `data/levels/index.json` を読み込み、有効な問題を取得して `game.js` で検証します。`main.js` は選択された問題から `GameSession` を作成し、盤面生成、入力イベントの登録、ヒントの描画を行います。

`game.js` はDOMにアクセスしません。`GameSession` が入力文字、時間、モード、検索回数、表示済み解答、終了状態を管理します。同じモジュールに解答判定、検索、文字の正規化も実装しています。時刻取得関数を差し替えられるため、実時間の経過を待たずに計測動作をテストできます。

`finishReason` は全問正解の `solved` と、途中終了して全解答を公開した `revealed` を区別します。`session.completed` はセッションが終了したことを表すため、それだけではクリア判定に使えません。

画面言語の設定は `localStorage` の `tracen-ui-language` に保存します。盤面、時間、使用回数はメモリ上のみで保持し、再読み込みでは復元しません。統計にはゲームごとのランダムIDを使い、未送信分は端末上に一時保存します。アカウント、端末フィンガープリント、継続的な訪問者IDは使いません。

本番サイトの `/api/` をPages Functionが受け、`STATS` サービスバインディングで独立Workerを呼び出します。Workerは `DB` でD1に接続し、データベースのトリガーで重複を防ぎながら集計します。途中終了はクリアに含めず、公開APIは集計値のみを返します。ローカルとプレビューは既定で本番統計を送信せず、送信失敗もプレイを妨げません。[デプロイと管理](docs/统计服务部署与维护.md)（中国語）を参照してください。

## 問題データと多言語対応

各問題を独立したJSONファイルで管理します。現在の問題はいずれもヨコ11問・タテ11問です。ウマ娘問題集の英字版とカタカナ版は登場キャラクターを揃え、`characterId` で対応付けます。maimai問題集は英語曲名のみで、`characterId` の代わりに整数の `songId` で `maimai.json` を参照します。詳細は楽曲データの出典文書を参照してください。

| 問題集 | `difficulty` | 英字の盤面 | カタカナの盤面 |
| --- | --- | --- | --- |
| 入門 | `beginner` | 24×24 | 19×20 |
| 発展 | `advanced` | 25×25 | 19×19 |
| 二つ名 | `epithets` | 23×24 | 20×18 |
| シンデレラグレイ | `cinderella` | 23×23 | 20×20 |

`difficulty` は以前の命名を残したフィールドで、問題集の分類を表します。アシスト／チャレンジのモードとは別です。各フィールドの規約は次のとおりです。

| フィールド | 規約 |
| --- | --- |
| `title`、`description`、`clues` | `zh-CN`、`en`、`ja` の3言語を必須とする |
| `answerLanguage` | 英字は `en`、カタカナは `ja` |
| `grid.layout` | 黒マスは `#`、入力マスは `.` |
| `row`、`column` | 解答の開始座標。0から数える |
| `characterId` | `characters.json` 内のキャラクターIDを参照 |
| `answer` | 解答言語の名前を正規化した文字列と一致する標準解答 |

英字の解答は大文字に統一し、空白と記号を除きます。カタカナは小さい仮名と長音符を保ち、1文字を1マスに入力します。入力時は半角カナ、ひらがな、結合濁点も正規化します。検索用の別名は標準解答には影響しません。

画面文言は `src/i18n.js`、ヒントは問題ファイル、名前は辞典で管理します。それぞれ独立しているため、訳名を変更する際はヒント内の参照や出典データも更新します。

## 問題の追加と保守

1. 必要なキャラクター、3言語の名前、検索用別名を `data/characters.json` に追加します。
2. 既存の問題と [Level Schema](schemas/level.schema.json) を参考に、盤面、解答座標、キャラクター参照、3言語のタイトルとヒントを作成します。
3. `data/levels/index.json` に一意のIDとファイル名を登録します。一覧の順序がメニュー順になります。`enabled: false` で問題を無効にできます。
4. 対になる英字版・カタカナ版のID末尾は `*-en`、`*-kana` とし、問題集とキャラクター集合を揃えます。盤面はJSONに明示的に記述し、アプリが検証・描画します。
5. テーマ別の出典記録を更新します。二つ名とシンデレラグレイのヒントは、対応する出典JSONと同期させます。
6. データ検証、テスト、ビルドを実行し、問題と成果物を読み込めることを確認します。

既存の問題集への追加は通常、データの変更だけで行えます。新しい分類を追加する場合は、`index.html` のメニュー、多言語の分類名、`game.js` の分類検証、問題用Schemaも更新してください。

盤面の検証では、3言語の項目、キャラクター参照、標準解答、座標範囲、交差文字、未定義の連続文字列、白マスの対応、番号順、全体の連結性を確認します。ビルド時は対になる問題のキャラクター集合とテーマ別出典の整合性も検証します。無効化した問題も保守用の検証対象ですが、画面には読み込まれません。

## ビルドとテスト

```sh
npm run check:data
npm test
npm run build
npm run preview
```

ビルドはNode.jsのファイル操作で実行し、JavaScriptの変換やバンドルは行いません。`dist/` を作り直し、`index.html`、`favicon.svg`、`src/`、`data/` をコピーします。モジュールとデータは相対URLを使い、静的HTTP環境で実行できます。ビルド時にテストは自動実行されないため、`npm test` を別途実行してください。

テストは入力の正規化、解答判定、計測と状態遷移、検索・解答表示の回数制限、途中終了、翻訳の不足、問題の分類・対になる版・キャラクター訳名の回帰を確認します。問題内容だけを変更する場合もデータ検証を実行してください。
