# 特雷森填字室

**简体中文** · [English](README.en.md) · [日本語](README.ja.md)

以《赛马娘》角色名和舞萌 DX 英文曲名为答案的多语言填字游戏。项目采用原生 HTML、CSS 和 JavaScript，通过 JSON 维护题库、角色/曲目词典和线索来源，游戏逻辑与界面交互分开实现。

界面与提示支持简体中文、英文和日语；填答文字支持英文和片假名，两者独立设置。当前包含五个题组、九套关卡、97位角色的名字词典和22首歌曲的曲目词典。

舞萌 DX 题组仅填英文曲名，每首至少有一张 13–15 级谱面（含 13+、14+）。线索由落雪 API 返回的曲师、社区别名、BPM 与谱面等级生成，可按曲名、曲师或别名查询。数字曲名及非英语标题首版不收录；不提供片假名答案。数据快照与更新命令见[舞萌 DX 题库与来源](docs/舞萌DX题库与来源.md)。

## 功能

| 功能 | 行为 |
| --- | --- |
| 选题 | 按题组、填答文字和具体关卡选择题目 |
| 辅助模式 | 完整答案正确后标绿，并显示角色的中、英、日名字；名字查询不限次数 |
| 答案帮助 | 辅助模式无限次查看，仅展示、不自动填入；挑战模式每局揭示3道不同题，自动填入、标绿并锁定。计时继续，重复查看不扣次数 |
| 挑战模式 | 未揭示答案隐藏正确性反馈，全部正确后通关；每局最多提交3次非空名字查询，未命中也计次。查询与揭示额度独立 |
| 提前结束 | 两种模式均可结束本局、停止计时并展示全部答案，与正常通关区分 |
| 名字查询 | 支持中文、英文、假名、名字片段和维护在词典中的别名；结果同时展示三种名字 |
| 输入 | 支持键盘导航、交叉格方向切换、整词粘贴和日语输入法 |
| 设置切换 | 切换界面语言或游玩模式保留盘面、计时和已用次数；更换关卡或填答文字并应用后重开一局 |
| 云端统计 | 按关卡与内容版本汇总开始局数、成功通关数和平均用时；另列全程挑战成绩，三语展示 |

计时从创建游戏会话开始，正常通关或确认提前结束时停止；设置、搜索和答案窗口不会暂停计时。查询与挑战揭示分别计数，切换模式不会恢复已用次数。辅助模式查看不占用挑战额度；挑战揭示的字母在两种模式中都保持锁定。查看过任何答案的成功局计入总通关，但不计入无答案帮助的全程挑战统计。

## 开发环境与命令

项目使用 Node.js 24 验证，不依赖第三方 npm 包，无需执行依赖安装。浏览器需要支持 ES Modules、Fetch API 和原生 `<dialog>`。

```sh
npm run dev
```

开发预览地址为 `http://localhost:5173/`。通过 HTTP 服务打开页面，以便加载模块和 JSON 数据。

| 命令 | 用途 |
| --- | --- |
| `npm run dev` | 从项目根目录启动本地静态服务 |
| `npm run check:data` | 检查关卡、名字词典、配对题目和来源数据的一致性 |
| `npm test` | 使用 Node.js 内置测试运行器检查游戏逻辑与题库约束 |
| `npm run build` | 校验数据，重新生成 `dist/` 静态产物 |
| `npm run build:worker` | 为统计 Worker 生成关卡版本与标准盘面 |
| `npm run preview` | 从 `dist/` 启动本地预览，需要先构建 |

在 Windows PowerShell 中可使用 `npm.cmd` 替代 `npm`。`启动游戏.cmd` 是 Windows 开发预览的快捷入口。服务读取环境变量 `PORT`，默认开发与产物预览都使用5173端口；同时运行时需指定不同端口。

## 运行机制

`catalog.js` 读取角色词典、曲目词典与 `data/levels/index.json`，加载已启用的关卡，并调用 `game.js` 校验数据。`main.js` 将选中的关卡交给 `GameSession`，据此创建盘面、绑定输入事件并渲染提示。

`game.js` 不访问 DOM。`GameSession` 管理填字内容、计时、模式、查询次数、已查看答案和结束状态；答案判定、搜索及文本归一化也在该模块中实现。构造会话时可注入时钟，便于测试时间相关行为。

结束状态通过 `finishReason` 区分：`solved` 表示全部答对，`revealed` 表示提前结束并公布答案。`session.completed` 表示会话已经结束，不能单独用它判断是否成功通关。

界面语言偏好保存在 `localStorage` 的 `tracen-ui-language` 中。盘面、计时和使用次数仅保存在内存中，刷新页面后不恢复。统计模块为每局生成随机 ID，网络失败时临时保存待上报记录；不使用账号、访客指纹或长期用户 ID。

生产站点通过同域 `/api/` 进入 Pages Function，再经 `STATS` 服务绑定调用独立 Worker，由其 `DB` 绑定写入 D1。开始、成功通关、提前结束分别记录，汇总由数据库触发器维护；单局明细不通过公开接口返回。本地和预览部署默认不写生产统计，统计不可用不影响游戏。部署及维护见[统计服务文档](docs/统计服务部署与维护.md)。

## 题库与本地化

每个关卡使用独立 JSON，当前均包含横向11题、纵向11题。赛马娘关卡的英文与片假名版本使用相同角色，分别排盘；编号、位置和方向可以不同，通过 `characterId` 对照。舞萌关卡仅有英文版，通过整数 `songId` 关联曲目词典，维护流程见上方题库来源文档。

| 题组 | `difficulty` | 英文盘面 | 片假名盘面 |
| --- | --- | --- | --- |
| 入门 | `beginner` | 24×24 | 19×20 |
| 进阶 | `advanced` | 25×25 | 19×19 |
| 专属称号 | `epithets` | 23×24 | 20×18 |
| 芦毛灰姑娘 | `cinderella` | 23×23 | 20×20 |

`difficulty` 是历史字段名，表示题目类别，与辅助/挑战游玩模式无关。语言字段使用以下约定：

| 字段 | 约定 |
| --- | --- |
| `title`、`description`、`clues` | 必须包含 `zh-CN`、`en`、`ja` 三份文字 |
| `answerLanguage` | `en` 表示英文，`ja` 表示片假名 |
| `grid.layout` | `#` 为黑格，`.` 为可填写格 |
| `row`、`column` | 答案起点，坐标从0开始 |
| `characterId` | 关联 `characters.json` 中的角色 ID |
| `songId` | 舞萌关卡关联 `maimai.json` 中的歌曲 ID，与 `characterId` 互斥 |
| `answer` | 标准答案，与对应语言的角色名或英文曲名归一化结果一致 |

英文答案统一为大写并去除空格、标点。片假名保留小写假名与长音，每个字符占一格；输入归一化支持半角假名、平假名和组合浊点。查询别名只影响搜索，不改变标准答案。

`src/i18n.js` 维护界面文案，关卡文件维护题目提示，角色词典维护名字。三处文字分别维护；修改角色译名时还需同步更新提示中的引用和相关来源数据。

## 新增与维护关卡

1. 在 `data/characters.json` 中补齐所需角色的三语名字和查询别名。
2. 参考现有关卡和 [Level Schema](schemas/level.schema.json)，编写盘面、答案坐标、角色关联、三语标题与提示。
3. 在 `data/levels/index.json` 中登记唯一 ID 与文件名。清单顺序决定菜单顺序；`enabled: false` 可停用关卡。
4. 对应的英文与片假名关卡使用 `*-en`、`*-kana` ID 后缀，并保持题组和角色集合一致。盘面由 JSON 显式维护，程序负责校验和渲染。
5. 更新主题题库的来源记录。专属称号和芦毛灰姑娘的提示需要与各自来源 JSON 同步。
6. 运行数据检查、测试和构建，确认题库与产物可正常加载。

在现有题组内增加关卡通常只需修改数据。增加新的题组类别时，还需更新 `index.html` 的菜单、三语类别文案、`game.js` 的类别校验及关卡 Schema。

题盘校验覆盖三语字段、角色关联、标准答案、坐标边界、交叉字、未声明的连续字串、白格覆盖、编号顺序与整体连通性。构建前还会检查双语答案版本的角色集合及主题来源一致性。停用关卡仍参与维护检查，但不会被网页加载。

## 构建与测试

```sh
npm run check:data
npm test
npm run build
npm run preview
```

构建使用 Node.js 文件操作，不转译或打包 JavaScript。脚本重新创建 `dist/`，复制 `index.html`、`favicon.svg`、`src/` 与 `data/`；模块和数据使用相对 URL，可在静态 HTTP 环境中运行。构建不会自动运行测试，应单独执行 `npm test`。

测试覆盖输入归一化、答案判定、计时与状态切换、查询与答案帮助配额、提前结束、三语文案完整性，以及关卡分类、配对与角色译名的回归约束。只修改题库内容时，也应运行数据检查。
